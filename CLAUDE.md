## Installation

No system dependencies — espeak-ng is vendored (see Dependencies), so `uv sync` is sufficient.

```bash
uv sync --group dev
uv run python -m unidic download   # one-time, ~1 GB, only needed for Japanese
uv run streamlit run streamlit_app.py
```

`.python-version` pins the interpreter to **3.12**, matching CI's `setup-uv` input, the `requires-python = ">=3.12"` floor, and `[tool.ty.environment]` — all four asserted by `TestPythonVersionConsistency`. Two things not to undo:

- **Don't delete the pin.** `uv sync` would fall back to interpreter discovery and take the first candidate satisfying `requires-python`, silently drifting local dev off the version CI gates on.
- **Don't raise ty's target above the floor** even when running a newer interpreter locally — type-checking against the declared floor is what catches accidental use of newer-only APIs.

Changing the pin makes the next `uv sync` rebuild the venv, which discards the ~1 GB UniDic dictionary (it installs into the venv's `unidic` package directory). Re-run the download afterwards if you use Japanese.

## Dependencies

**System: none.** espeak-ng is *not* a system dependency here — `espeakng-loader` ships a prebuilt `libespeak-ng.dylib` plus `espeak-ng-data` inside the wheel, and `misaki/espeak.py` calls `EspeakWrapper.set_library()` / `set_data_path()` on those at import. phonemizer's `EspeakWrapper.library` resolves lazily and checks its `_ESPEAK_LIBRARY` class attribute *first*, ahead of `$PHONEMIZER_ESPEAK_LIBRARY` and `ctypes.util.find_library('espeak-ng')`, so the system lookup is unreachable once misaki has been imported. This covers synthesis too: mlx-audio's kokoro pipeline imports `misaki.espeak` rather than touching phonemizer directly, and nothing in mlx-audio shells out to an `espeak` binary. **`brew install espeak-ng` therefore changes nothing — don't add it to setup docs or CI.** `TestEspeakVendoring` fails the build if a `brew install` reappears in `ci.yml`, if the wheel stops shipping the library/data dir, or if misaki stops binding phonemizer to it.

> **Keep the venv path short.** espeak-ng stores its data directory in a fixed 160-byte `N_PATH_HOME` buffer. If the resolved `espeakng_loader/espeak-ng-data` path exceeds it, the path is truncated, espeak falls back to the build-machine path baked into the wheel (`/Users/runner/work/espeakng-loader/...`), fails to find `phontab`, and calls `exit(1)` directly — the process dies with **exit code 1, no Python traceback, no pytest summary, and buffered output lost**. It reads like a mysterious interpreter-specific crash. To check a given checkout, measure the resolved data directory — `<venv>/lib/pythonX.Y/site-packages/espeakng_loader/espeak-ng-data` — and keep it comfortably under ~159 characters; a `.venv` in the repo root is normally fine, while a venv under a deeply nested CI cache or temp directory may not be. (The 160-byte figure is inferred from the observed truncation boundary, not read from espeak-ng's source, so treat it as approximate.) Since `misaki/espeak.py` calls `EspeakWrapper.set_data_path()` at import time, a later override cannot fix it — espeak is already initialized.

**Runtime:** `en-core-web-sm` (pinned URL; the wheel declares no spaCy requirement, so the resolver never flags a mismatch — bump it on a spaCy *minor* upgrade and confirm with `uv run python -m spacy validate`), `espeakng-loader`, `misaki[ja]`, `misaki[zh]`, `mlx-audio`, `num2words`, `numpy`, `phonemizer-fork`, `soundfile`, `spacy`, `streamlit`. The English G2P stack (`spacy`, `num2words`, `phonemizer-fork`, `espeakng-loader`) is pulled in directly rather than via `misaki[en]` to skip `spacy-curated-transformers`, which drags in `torch`; both are absent from `uv.lock` as a result. (`transformers` is still present, pulled directly by `mlx-audio`.) Japanese needs the one-time UniDic download.

**Dev:** `ruff`, `ty`, `pytest`

## Configuration

`pyproject.toml` — project metadata, dependencies, dependency groups, ruff isort (`combine-as-imports`), pytest (`pythonpath`, `testpaths`), ty (`python-version = "3.12"`).

`.streamlit/config.toml` — `[server] fileWatcherType = "none"`, `[browser] gatherUsageStats = false`, and the **"Ai-iro" dark theme**: a `[theme.dark]` block plus `[theme.dark.sidebar]`, and deliberately nothing else under `[theme]`, so light mode stays Streamlit's stock theme and the System/Light/Dark menu survives. `TestStreamlitConfig` guards every setting and its docstring is the single authoritative statement of why (the two sidebar accents, the pinned page colours, the 0.6 caption opacity); don't restate it here or in the config comment. Streamlit's own default palettes live in its frontend bundle, not in `config.py`, so never hand-copy their hex values into this file or these docs — name the option keys instead. The dark theme pins its own page colours for exactly that reason: its contrast tests compute every pair from the TOML alone.

Light mode is the stock theme, and two of its properties are worth knowing before anyone treats them as bugs in this repo. Default `primaryColor` renders **#ff4b4b** (pixel-sampled, not inferred), which is ~3.3:1 against the white button text — below WCAG AA's 4.5:1 for normal text. That same #ff4b4b is also light mode's default `redColor`, but `_render_length_caption`'s red band is not drawn in it: `:red[…]` text uses `redTextColor`, a separate text shade (see that option's description in Streamlit's `config.py`), so the band never matches the Play buttons. And the stock `st.toggle` ("Show all voices") draws its off-state track at about 1.45:1 against a light page, under WCAG 1.4.11's 3:1 for control boundaries. Dark mode clears all of these, and one stock dark had too — its red caption band drew at ~3.1:1 once `st.caption`'s 0.6 opacity is counted, which a CSS-colour check misses. Two dark-mode limits no theme key reaches: every button's focus ring is the primary at 50% alpha (~1.75:1 against the page), and a hovered or focused Play darkens to ~2.1:1 against it while its label stays above 9:1.

> **The dark-only block rests on frontend behaviour, not a documented contract.** Streamlit's theming docs still say the mode menu needs *both* `[theme.light]` and `[theme.dark]`; the 1.64 bundle actually builds all three variants when *either* is non-empty and fills unset keys from that mode's stock base. After any Streamlit upgrade, load the app and confirm the ⋮ menu still offers System/Light/Dark and that light mode still matches a build with the theme blocks removed — if either regresses, a lone `[theme.dark]` has silently pinned or restyled light mode.

> **`gatherUsageStats = false` is what makes the offline claim true — don't drop it.** Streamlit's frontend posts session telemetry to `data.streamlit.io` on every session unless that key is set, and the option **defaults to `true`**, so its mere absence is not safe. With it off, and with no theme font pulling `fonts.googleapis.com` stylesheets (`TestStreamlitConfig.test_theme_loads_nothing_remote`), the rendered page issues no outbound requests — the browser half of what README's "no network calls" line and the "Runs offline" badge assert. The server half is `ensure_repo_downloaded` trying the local cache first, then `load_pipeline` loading from the snapshot path and pinning `model.repo_id` (see Key Functions). Re-check after any Streamlit upgrade by loading the app and evaluating `performance.getEntriesByType('resource')` in the console: every host must be `localhost` (Streamlit self-hosts its Source Sans woff2, so a `fonts.googleapis.com` entry means a theme font crept in). (`TestStreamlitConfig.test_usage_stats_stay_off`)

## CI & Releases

`.github/workflows/ci.yml` holds both jobs. **Version-specific detail lives in the workflow's own comments — change it there, not here, so there is one place to update per bump.**

### `lint-typecheck-test` (merge gate)

Push to `main` + every PR, `macos-latest` only (mlx/mlx-metal are `darwin`-gated in `uv.lock`), `timeout-minutes: 20`, `contents: read`. Runs `uv sync --locked --group dev` (fails on lockfile drift) → `ruff check .` → `ruff format --check .` → `ty check` → `pytest`. Note CI gates on `ruff format --check .`, not the bare `ruff format .`. Steps omit `name:` so GitHub labels them with the command itself. `tests_integration/` is excluded (needs the real modules + the ~355 MB download). Keep `python-version: "3.12"` in the `setup-uv` block — `TestPythonVersionConsistency.test_ci_workflow_matches` asserts on it.

`cancel-in-progress` is the expression `${{ github.ref != 'refs/heads/main' }}`, never `true`: superseded PR runs are still cancelled, but cancelling a main run between the release job's tag push and its publish would strand a tag with no release. The same concurrency group without cancellation makes main runs *queue*, so a later run always observes the tag an earlier one pushed. (`TestReleaseWorkflow.test_main_runs_are_never_cancelled_mid_publish`)

Three standing policies:

- **No system packages.** See Dependencies. Guard: `TestEspeakVendoring`.
- **Pins do not float.** `astral-sh/setup-uv` carries a full version (it has published no major tags since v7). `actions/checkout` is pinned per job by token scope — a floating major tag is repointable upstream, so the `contents: write` release job gets a SHA. Guard: `TestReleaseWorkflow.test_release_job_checkout_is_sha_pinned`. None of these refresh themselves, which is what `.github/dependabot.yml` is for; `uv`'s own pin should track the local `uv --version` — not `.venv/pyvenv.cfg`, whose `uv =` line only records the uv that created the venv.
- **Cache is pruned explicitly.** setup-uv v9 flipped `prune-cache` to `false`; at that default this repo would save its entire uv cache per lockfile hash against GitHub's per-repo quota, so `ci.yml` sets it back to `true`. The cost runs the other way: `uv sync` re-fetches wheels from PyPI instead of reading them back out of the cache.

### `release` job

Fully automatic on a version bump. The flow is just **bump `version` in `pyproject.toml` → `uv lock` → commit → push to `main`**. No manual tagging.

`ubuntu-latest` (no build/test — that is the other job's), `needs: lint-typecheck-test` so a red tree cannot ship, gated `if: github.event_name == 'push' && github.ref == 'refs/heads/main'` so PRs — fork PRs especially — never reach the `contents: write` token. That token is granted **per job**, so `lint-typecheck-test` (which executes third-party code via `uv sync`) stays `contents: read` (`TestReleaseWorkflow.test_release_job_mirrors_version_guard`). Three steps: annotated `git tag -a vX.Y.Z` + push → `gh release create --draft --notes-file … --verify-tag` → `gh release edit --draft=false`. Drafting first means a failure between steps leaves an invisible draft, not a half-formed public release; GitHub auto-marks the newest published release "Latest", so no `--latest`.

Three decisions that are easy to undo by accident:

- **Bump detection asks whether the tag and release already exist** — never diffs against the parent commit, which breaks on squash merges, multi-commit pushes, and re-runs. So every push to `main` enters the job and the common case is a three-step skip. States: `absent` (tag — only when `tag_exists == 'false'`, so a mid-flight re-run drafts and publishes without re-tagging — then draft, then publish), `draft` (publish only, finishing a job that died mid-flight), `published` (skip). Version must be exactly `X.Y.Z` or the job errors (`TestReleaseWorkflow.test_pyproject_version_is_grep_extractable`). For prereleases, add PEP 440-aware normalisation and pass `--prerelease`.
- **Notes come from `release_notes.py`, not `--generate-notes`.** That flag enumerates merged *pull requests* only, and this repo pushes straight to `main` and has never opened one, so it produced nothing but a compare link no matter what shipped. Hence `fetch-depth: 0` on the release checkout (the script reads `git log <previous>..<tag>` locally) and a `previous` output on the `plan` step resolved from `releases/latest`, drafts and prereleases excluded. This only works while commit subjects stay conventional, which `TestWorkflowBinding.test_repo_history_is_fully_categorised` enforces over the last 40 commits.
- **There is deliberately no tag-triggered `release.yml`.** It published from a hand-pushed tag without consulting CI, and a second publish path risks double-cutting one version. `TestReleaseWorkflow.test_tag_triggered_release_workflow_stays_retired` fails the build if it reappears. To re-cut a release, delete the GitHub release (and its tag) and re-run the CI job.

## Code Style

- snake_case for functions/variables, PascalCase for classes; type annotations on all parameters and returns; isort with `combine-as-imports`.
- `pyproject.toml` sets no `[tool.ruff.lint] select`, so the project runs on **ruff's default rule set** — which ruff 0.16 widened from 59 rules to 413 (this is what first enabled the `I` isort rules the repo had configured but never enforced). A ruff upgrade can therefore surface new findings with no code change; run `ruff check .` after every bump rather than assuming a clean tree stays clean.
- Every `except Exception` in `streamlit_app.py` carries `# noqa: BLE001` deliberately — the first-launch download guard, the per-card Play handler, and the Tokenize handler. Each must degrade in place (`st.error` / in-card `st.exception` / `_tokenize_error_message`) instead of leaking a traceback into the UI. Don't narrow them to satisfy the linter.
- **Asserting about a config file:** parse it where a parser exists (`tomllib` for `.streamlit/config.toml` and `pyproject.toml`). Where you must substring-match — `ci.yml` — match against a **comment-stripped** view, never the raw text; `TestReleaseWorkflow._release_job_directives` is the helper (copies live in `TestEspeakVendoring` and `tests/test_release_notes.py`). This repo documents each policy in prose directly above the line implementing it, so a raw check is satisfied by the explanation whether or not the policy survives: `assert "contents: write" in job` passed against the comment `# ... this job runs with \`contents: write\``, and so stayed green when the `permissions` block was deleted *or* hoisted workflow-wide. Anchor flags too — `assert "--draft" in job` is a substring of the publish step's `--draft=false`. Verify such a test by deleting the line it guards and confirming it fails; "it passes" proves nothing here.
- When working with Python, invoke the relevant `/astral:<skill>` for uv, ty, and ruff.

## Architecture

### Files

- `streamlit_app.py` — the whole app: config constants, G2P, synthesis, and rendering. See Key Functions and UI below.
- `release_notes.py` — builds every GitHub Release body from conventional-commit subjects: `parse_commit` classifies a subject, `render` groups them under `SECTIONS`. Two deliberate choices: it is **stdlib only**, so the release job needs no Python setup beyond the runner image's `python3`; and an unrecognised subject is kept **verbatim** under `Other Changes` rather than dropped or de-prefixed, because a silently omitted commit understates the release with no signal that it did. Breaking changes lead *and* repeat under their own type, so skimming headings cannot miss one.
- `voice_grades.py` — `VOICE_GRADES`, `_GRADE_RANK`, and `_grade_rank`, extracted from the Kokoro model card; consumed by the voice picker for sorting and labeling.
- `samples/` — public-domain sample text, 9 directories × 3 files: `random.txt` (one quote per line, a pool) plus two literary excerpts. Referenced by `SAMPLE_BUTTONS`, read by `_load_sample`.
- `README.md` — user-facing docs (install, usage, troubleshooting), the screenshots, and the third-party GPLv3/LGPL acknowledgements. It duplicates several facts held here, so update both; its tagline, MIT badge and license link are asserted by `TestProjectMetadata`/`TestLicensing`.
- `assets/` — `screenshot-dark.png` alone, the full-width README hero, with layout-describing alt text. It shows the app **mid-session**, not at initial render: the sidebar expanded (Language, Voice gender, Pronunciation tips), sample text loaded, Tokenize run so the length caption and phoneme expander (one unwrapped line, cut off at the block's edge) are populated, and the top voice card generated so it carries its Cached badge and player-and-Download row; the six cards end on the switched-off "Show all voices (14 more)" toggle. (Idle framing hides the accent colour entirely — with the text area empty, every Play button is disabled.) Changes to the UI section below make it stale; recapture with `scripts/capture_screenshot.py`.
- `scripts/capture_screenshot.py` — regenerates that hero. A script because all nine ways the capture goes wrong (listed in its docstring) yield a *plausible but wrong image*, not an error. `wait_for_cards` counts all six Play buttons, not just the column. The post-Tokenize wait is on the "Phoneme tokens" label and `stCode`: `text="Phonemes"`, a case-insensitive substring match, hit the length caption. `drive()` requires `stSidebar[aria-expanded="true"]` (collapsed, it is off-canvas yet still anchors) and parks the mouse at `(WIDTH - 4, 4)`, since hovering the sidebar draws its « button. `CROP_ANCHORS` crops at the bottom edge of one `(text, testid)` block per region — phoneme expander, "Show all voices" toggle (`stCheckbox`: `st.toggle` has no testid of its own, just a `role="switch"` input inside that one), tips box — and `anchor_bottom` demands exactly one match. `crop_height` refuses a crop past `HEIGHT` (a non-full-page shot silently clips to the viewport) and any `content_bottom` below the crop line, measured in both `CONTENT_ROOTS` — `.stMainBlockContainer` and `stSidebarUserContent`, not their padded boxes nor the whole sidebar (its resize handle is a viewport-tall leaf); a missing root raises. At 1600 px the voice list is the lowest region: the toggle's anchor ends at 783.19 px, 1.5 px under `content_bottom` (its 24 px box wraps a 21 px label), for an 831 px crop (3200×1662), and a 72 px block injected under the toggle (reaching 863 px) trips the refusal; a stale anchor in a region ending above the line — today the composer and sidebar — goes unseen. Run via `uvx --with playwright` (not a dependency: it pulls a browser), hence the import's `# ty: ignore[unresolved-import]`, without which CI's `ty check` fails (verified).
- `LICENSE` — MIT (declared via `license = "MIT"` + `license-files = ["LICENSE"]` in `pyproject.toml`); runtime deps add GPLv3/LGPL terms — see README acknowledgements.
- `.python-version`, `.streamlit/config.toml`, `.github/workflows/ci.yml` — see Installation, Configuration, and CI & Releases.
- `.github/dependabot.yml` — weekly `github-actions` update PRs (`commit-message.prefix: "ci"`). This is the refresh mechanism for the pins that cannot float. Python dependencies are deliberately **not** covered — those go through `uv add`/`uv lock`.
- `.claude/settings.json` — shared guardrails, the only `.claude/` file checked in (a `.gitignore` exception; per-user `settings.local.json` stays ignored). `permissions.deny` blocks edits to `uv.lock` (change deps via `uv add`/`uv remove`/`uv lock`); `permissions.ask` prompts on `.python-version` — **ask**, not deny, because changing the pin is supported, it just needs the UniDic re-download acknowledged first. Keep both as **native permission rules, not a `PreToolUse` hook**: only native rules cover every file-editing tool, survive case-insensitive path variants, and get built-in deny-circumvention detection (`sed -i`/`cat >`/`uv python pin` routed via Bash). Each is a lone `Edit(path)` rule on purpose: Claude Code checks path rules only in that form and applies it to Write too, and warns at every startup about `Write(path)` rules and about `MultiEdit`, which is no longer a tool — so don't add them back for completeness. A `PostToolUse` hook (matcher `Edit|Write` — hook matchers, unlike path rules, name each tool) then runs `ruff check --fix` **then** `ruff format` (that order: lint fixes reorder imports, formatting cleans up) on `.py` files under `$CLAUDE_PROJECT_DIR`, exiting `2` if either fails so unfixable lint surfaces to the agent instead of being swallowed.
- `tests/conftest.py` — mocks `streamlit`, `mlx_audio`, `misaki`, `huggingface_hub` for import; the `streamlit` mock gives `cache_resource`, `cache_data`, and `fragment` identity pass-through shims — one `_passthrough_decorator` factory, since all three need the same two-shape handling — so decorated functions keep running their real bodies. The factory also records the options each decorator was given into `DECORATOR_KWARGS`, because handing the bare function back is precisely what throws those options away; `TestCacheSpinners` is the only thing that can then see them. The `st.columns` mock takes `**kwargs` for the same reason a bare `lambda f: f` failed: a positional-only lambda fails collection of the whole suite the moment a call site passes `gap=`. The `selectbox`/`segmented_control` mocks return real values only for the labels `"Language"` and `"Voice gender"` and for any label starting `"Speed for "` (each card's speed label names its voice) — any other label silently yields a MagicMock, so rename a widget label and its mock entry together.
- `tests/test_streamlit_app.py` — the unit suite. Config-file invariants live here alongside the app tests: `TestPythonVersionConsistency`, `TestProjectMetadata`, `TestLicensing`, `TestReleaseWorkflow`, `TestEspeakVendoring`, and `TestStreamlitConfig`.
- `tests/test_release_notes.py` — the only thing exercising `release_notes.py` (it runs solely inside the release job, where a bad body is visible only after publishing). `TestWorkflowBinding` ties `ci.yml` to the script.
- `tests_integration/conftest.py` — clears `streamlit`, `streamlit_app`, `misaki`, `mlx_audio`, `huggingface_hub` from `sys.modules` so AppTest gets the real modules (`streamlit_app` needs its own prefix entry — the `streamlit` prefix doesn't match it). Incompatible with `tests/conftest.py`'s mocks in one process, so `testpaths = ["tests"]` keeps this suite opt-in.
- `tests_integration/test_app_integration.py` — AppTest tests over initial render, sidebar/main placement (`TestSidebar`, see UI), the "Show all voices" toggle (`TestShowAllVoices`, see UI), sample buttons, Tokenize/Play enablement, gender filter, language switching (driven through `at.sidebar.selectbox(key="language")`), per-card speed. Feeds `AppTest.from_file` an **absolute** `APP_PATH` — streamlit 1.61 changed relative-path resolution from the working directory to the directory of the calling file, so the bare `"streamlit_app.py"` this used to pass now raises `FileNotFoundError`.

### Key Functions

Only the entries with a non-obvious contract are listed; the rest of `streamlit_app.py` (`get_voices`, `load_tokenizer`, `_create_g2p`, `tokenize_text`, `generate_speech`, `_filter_voices_by_gender`, `_gender_code_from_selection`, `_audio_to_wav_bytes`, `render_phonemes`, `_render_persistent_phonemes`, `_render_length_caption`, `_load_sample`, `_render_sample_buttons`) does what its name says.

- `load_pipeline` — cached global model via `mlx_audio.tts.utils.load_model`, deferred to the first Play click. It loads `Path(ensure_repo_downloaded())`, not `REPO_ID`: handed a repo-id string, mlx-audio's `get_model_path` runs an online `snapshot_download` that asks huggingface.co for the latest revision on the first Play of every launch — offline it falls back to the cache, so the only casualty was README's "no network calls", silently. `model_type="kokoro"` because mlx-audio otherwise infers the type from the path — the directory after the first `hub` component, else the commit-hash directory — which yields `kokoro` only while the cache directory, as `snapshot_download` resolves it, is itself named `hub` (`TestLoadPipeline.test_loads_from_the_local_snapshot`, which also fails if any `snapshot_download` call drops `local_files_only`). **Must set `model.repo_id = REPO_ID` before returning:** mlx-audio's loader builds `Model(config)` without forwarding a repo id, so `Model.repo_id` stays `None` and its `_get_pipeline` falls back to the class constant `REPO_ID = "prince-canuma/Kokoro-82M"` when it creates (and caches) each per-language `KokoroPipeline`. Unpinned, every voice's first Play re-downloads a tensor already present in our snapshot and raises a raw `RuntimeError` when offline. Guarded by `TestLoadPipeline.test_pins_voice_repo_to_our_snapshot`.
- `ensure_repo_downloaded` — `huggingface_hub.snapshot_download` once per process; tries `local_files_only=True` first so the ~355 MB spinner appears only when files are actually missing.
- `generate_one` — **deliberately does not tokenize.** mlx-audio's `KokoroPipeline` builds its own G2P *and runs it* on every generation: `Model.generate` (`kokoro.py:293`) resolves a per-language pipeline and calls it (`:313`), and `KokoroPipeline.__call__` invokes `self.g2p` at `pipeline.py:447` and `:510`. Cite those call sites, not the `__init__` branches at `pipeline.py:152`–`167` — construction alone would not make a pass here redundant, invocation is what does. So a pass here is a second one over the same text; on a Play with no prior Tokenize it also built this app's whole G2P stack (spaCy + the espeak fallback) on the click path and kept that duplicate resident for the session. Measured ~1.4 s of the first Play, spent filling a `VoiceResult["phonemes"]` field that nothing read — hence no such field. Phonemes reach the UI only via the Tokenize button and `st.session_state["last_phonemes"]`. Guarded by `TestGenerateOne.test_does_not_build_a_tokenizer`.
- `_tokenize_error_message` — friendly text for a Tokenize failure. `lang_code == "j"` plus "unidic" in the error returns the `uv run python -m unidic download` recovery command (the dictionary lives in the venv and vanishes on any rebuild); everything else gets `Could not tokenize this text: {error}`. The hint is Japanese-only on purpose — `TestTokenizeErrorMessage` fails if another language claims it.
- `_render_tokenize_row` — the Tokenize button (disabled on empty or whitespace-only text) and the length caption, in an order that is the contract. Inside an `st.container(horizontal=True, vertical_alignment="center")` row: the button, then a caption slot reserved with a bare `st.container()`. After the row closes: a click runs `tokenize_text` and stores `(text, lang_code, phonemes)` in `st.session_state["last_phonemes"]`, so `load_tokenizer`'s first-use cache spinner and any `st.error(_tokenize_error_message(...))` span the column below the row — tokenized inside it, the spinner was a flex item that knocked the caption onto a second line for the ~1.3 s load. Last: `_render_length_caption` into the slot, so the click that tokenizes already shows the exact count — the voice card's reserve-then-fill title, again. `TestRenderTokenizeRow`, every test mutation-verified: `test_tokenize_is_disabled_until_there_is_text`, `test_button_and_caption_slot_share_a_centred_row`, `test_click_stores_the_tokenization`, `test_no_click_does_not_tokenize`, `test_tokenizes_with_no_row_open`, `test_a_failed_tokenize_is_one_error_below_the_row` (generic and Japanese missing-UniDic), `test_caption_follows_this_runs_tokenization`, `test_caption_shows_the_estimate_before_any_click`. It patches `streamlit_app.load_tokenizer`, not misaki, so conftest's shared misaki mocks gain no calls. In AppTest, `TestSidebar.test_tokenize_row_and_phoneme_readout_render_in_main` pins the button, caption and phoneme block to main, the caption into the button's horizontal row, and its exact count after a click.
- `_text_digest` — stable 16-hex-char `hashlib.sha1` digest, so cache keys are reproducible across processes (unlike the previously used `hash()`, which is per-process randomized).
- `_cache_key` — `f"audio:{voice}:{lang_code}:{speed}:{_text_digest(text)}"`. Cache invalidates implicitly when any of voice/text/speed/lang changes.
- `_next_audio_seq` — monotonic counter from `st.session_state["_audio_seq"]`, stamped onto each `VoiceResult` at write time so cache ordering never relies on `st.session_state` iteration order (a hash-ordered set in real Streamlit, not insertion order).
- `_stale_cached_key` — key of the most recently generated audio for a `(voice, text, lang)` regardless of speed (highest `seq`), or `None`. Drives the cached badge, the stale-preview player, and the protect-map registration. `_find_stale_cached_audio` is a thin wrapper returning that key's value, retained for its unit tests (production reads the value inline).
- `_evict_old_audio` — caps the session-state cache at `AUDIO_CACHE_LIMIT` (20), deleting lowest-`seq` first. Takes an optional `protect` set: the main body resets `st.session_state["_displayed_card_keys"]` (a `voice → displayed key` dict) each full rerun and every card's fragment writes the key it is actually showing, so a fragment's eviction can't orphan a sibling card's visible player — including a stale-preview player at another speed. **`protect` orders the queue, it does not remove keys from it**: unprotected keys go first, displayed ones only if the cap still isn't met. An absolute veto is only safe while no language ships more than `AUDIO_CACHE_LIMIT` voices, since each card protects one key — American English has exactly 20 against a limit of 20, so one voice added upstream would leave nothing evictable and silently turn the cap into one clip per voice. (`TestEvictOldAudio.test_cap_still_holds_when_every_key_is_protected`)
- `render_voice_card` — `@st.fragment`, so a Play or speed interaction reruns only that card. It opens its own `st.container(border=True)` **inside the function**; never pass a pre-built container in, or the cards share a fragment instance. The **title is reserved with a bare `st.container()` as the first child of the card's one row, and written at the end**, because its badge depends on whether the card has audio and on the generating run it does not yet — emitted in place, the one card that had just produced a clip was the only card without a badge until an unrelated rerun fixed it. `st.container`, not `st.empty`: a placeholder clears at the top of each rerun, remounting the title every fragment run. Re-entering the slot after the row's `with` has closed still draws into the row, which is what lets the title be written last yet sit on the controls' line. Guards in `TestRenderVoiceCard`, each verified by mutation: `test_badge_appears_on_the_run_that_generates` pins the badge's *timing*; `test_opens_its_own_containers_in_order` pins every container's role at once by asserting the whole four-call `st.container.call_args_list` for an idle card — `call(border=True)`, `call(horizontal=True, vertical_alignment="center")`, `call()`, `call(horizontal=True, width="content", gap="xsmall")` — since `st` is one MagicMock and every container is otherwise the same object. Moving an element into or out of a `with` changes no call at all, so placement goes through `_render_tracking_containers`, built on the module-level `_ContainerTracker` (the suite's one copy of the technique, shared with `TestRenderTokenizeRow` and `TestRenderSampleButtons.test_buttons_share_one_wrapping_row`), which gives each container a real enter/exit and records the open stack at each creation and draw: `test_title_is_written_into_the_reserved_slot` (slot created in `(card, row)`, title written with `(card, title_slot)` open — the row has closed by then), `test_speed_and_play_wrap_together_in_the_controls_group`, `test_player_and_download_share_a_row`, `test_stale_preview_is_caption_over_player_without_download`. `test_speed_and_play_share_a_fixed_width` pins `CARD_CONTROL_WIDTH` on both controls, and `test_card_control_width_clears_the_measured_label_floor` holds it at or above the measured 78 px floor. Generation renders into an `st.empty()` placeholder cleared on success only, once the clip is stored — `test_play_clears_its_progress_once_the_clip_is_stored` pins open → generate → close → clear with the clip already in session state (not where the clear falls relative to eviction), and `test_failed_play_leaves_its_progress_in_place` with one case per error branch, so clearing it in a `finally` or in any one `except` fails. Its speed selectbox carries `persist_state="session"`, without which a tail card loses its speed while "Show all voices" is off (see UI below). It plays and serves `VoiceResult["wav"]` directly and sets `on_click="ignore"` on the Download, so a click neither re-encodes nor reruns the fragment.
- `_format_voice` — card title, `Name (gender) — grade` (or `Name (gender)` ungraded). The spaces round the dash are **no-break** (`\u00a0`) so a title too long for its slot breaks between the name and `(gender) — grade`; plain spaces stranded the grade alone on a second line ("Nicole (female) —" over "B-") just above the one-line switchover. (`TestFormatVoice.test_a_long_title_breaks_before_the_gender_not_the_grade`)
- `_split_voices_for_display` — returns `(visible, hidden)`, top `top_n` (default 6) visible. A `selected` voice landing in the tail is pinned into the visible section — a path production never takes (the app always passes `None`), kept for `TestSplitVoicesForDisplay`.
- `_estimate_phonemes` — stripped char count × `_PHONEME_MULTIPLIERS` (`a`/`b` 0.85, `e`/`f`/`p` 0.90, `h`/`i` 1.00, `j` 1.40, `z` 2.00; unknown code → 1.0). Used by the length caption before any tokenization has run.
- `_phoneme_band` — `(color, label)` for a phoneme count, per VOICES.md guidance: `<20` red "very short", `20–99` orange "short", `100–399` green "ideal", `400–509` orange "long", `≥510` red "will be chunked".
- `_pick_sample` — full excerpt, or a random non-empty line from a `random.txt` pool. The random branch avoids repeating the previous pick via `st.session_state["_last_random_{lang}_{filename}"]`, re-rolling only when the pool has more than one line.
- `_set_text_from_sample` — `on_click` callback writing into `st.session_state["text_input"]`. It **must** run between reruns, or Streamlit raises "widget key already instantiated".

### Model, Languages & Voices

[Kokoro-82M-bf16](https://huggingface.co/mlx-community/Kokoro-82M-bf16) via `load_model` from `mlx_audio.tts.utils` — 82M params in bf16, 24000 Hz, MLX backend for Apple Silicon. Nine languages: `a` American English, `b` British English, `e` Spanish, `f` French, `h` Hindi, `i` Italian, `j` Japanese, `p` Brazilian Portuguese, `z` Mandarin Chinese.

**Adding a language touches five places in lockstep:** `LANGUAGES`, `ESPEAK_LANGUAGES` (unless it has a dedicated misaki G2P like `j`/`z`), `_PHONEME_MULTIPLIERS`, `SAMPLE_BUTTONS` + three files in `samples/<code>/`, and `VOICE_GRADES` if graded. `test_language_count` hard-codes 9 and the `*_covers_all_languages` tests fail on any partial edit.

Voice files are named `{lang}{gender}_{name}` (e.g. `af_heart`) with a `.safetensors` extension. `get_voices` walks the snapshot's `voices/` directory and sorts by quality grade from `VOICE_GRADES` (sourced from [VOICES.md](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)), ties alphabetical; ungraded voices (Spanish, Brazilian Portuguese, anything new) sort last. Voices added upstream need the HuggingFace cache cleared to appear. After the initial download the app is fully offline — but only because `load_pipeline` loads from the snapshot path and pins `model.repo_id`.

### Performance

- MLX runs natively on Apple Silicon — no PyTorch or MPS fallback.
- `@st.cache_resource` for the model, the per-language tokenizers, and the snapshot path; `@st.cache_data` for per-language voice lists (a local filesystem walk, no TTL needed). All three `cache_resource` sites set `show_spinner` explicitly, because the default renders ``Running `load_pipeline()`.`` — the Python identifier — at exactly the three moments the app makes a user wait (`cache_utils.py:692`). `ensure_repo_downloaded` passes `False` since it renders its own message; the other two pass a sentence. This is why `tests/conftest.py` builds its shims with `_passthrough_decorator`, which accepts being handed either the function or the options — a bare `lambda f: f` fails to collect the entire suite the moment any call site is parameterized. `TestCacheSpinners` guards all three settings (verified by mutation: dropping any one, stacking a second message on the download guard, or letting the function name back into the text each fail).
- Model load is deferred to the first Play click, so initial render isn't blocked. That click builds **one** G2P stack, not two — see `generate_one`.
- `generate_speech` uses `np.asarray(..., dtype=np.float32)` to avoid copying chunks that are already float32.
- `render_voice_card` being a fragment means a Play click reruns one card, not the script. One accepted trade-off: a sibling card's cached badge refreshes on the next full rerun, not instantly.
- The voice list is lazy: the tail's cards are built only while "Show all voices" is on (see UI), so the default page pays for six cards per rerun, not American English's twenty.
- Each clip is encoded to WAV **once, at generation**, and cached as bytes. Passing samples to `st.audio` looks free but re-encodes on every render — a float64 copy, an int16 conversion, a WAV write and a hash — so the player, not just the download, was paying per rerun. Bytes also make the cache smaller than the float32 arrays they replace.

### UI

Layout is `st.set_page_config(layout="wide", …)` (first command) → `st.title` → the first-launch download guard → an orientation `st.caption` → the sidebar → `st.columns(2)` as `input_col` (the composer) and `voices_col`. Generated audio renders inline inside each card; there is no separate output row.

The caption sits **after** the download guard on purpose: above it, an orientation line promising offline synthesis would render over the one-time ~355 MB download and directly above its failure message. The sidebar comes after both, so a failed first launch never draws it.

**Sidebar:** the settings that decide *which* voices main shows, plus a note consulted rather than read in order. The text and the voices are the content and stay in main, since on a phone the sidebar starts collapsed. In order: the `Language` selectbox (visible label, stretched to the sidebar — the fixed 320 px it once carried only stopped a full-viewport dropdown under the title reading as a banner) → the `Voice gender` `st.segmented_control`, its label visible now that it no longer sits directly over the cards it filters, with `required=True` so one segment is always selected and there is no empty state (`"All"` maps to `None` via `_gender_code_from_selection`) → `PRONUNCIATION_TIPS` in a bordered `st.container` headed `:material/lightbulb: **Pronunciation tips**`. It keeps Streamlit's default width: a 256 px sidebar gave main 44 px but split the tips' code spans mid-token (`[Kokoro](/k` / `ˈOkəɹO/)`). `TestSidebar` pins the placement by reading `at.sidebar` and `at.main` separately — `at.selectbox(key=…)` searches both roots, so it passes wherever a widget lands — along with both labels' visibility (`widget.proto.label_visibility.value`) and the tips' single bordered box.

The tips box is deliberately **not** `st.info`. Streamlit's alert renders `role="status"` for info and success (error and warning get `role="alert"`), an ARIA live region that asks a screen reader to announce it as a status update — wrong for permanent reference content, and at odds with keeping the sample-button emoji out of the accessible name for the same reason.

**Composer (left column):** a `TEXT_AREA_HEIGHT` (300 px) `st.text_area`, no character cap → the per-language sample buttons from `SAMPLE_BUTTONS` (random-quote plus two excerpts, each wired `on_click=_set_text_from_sample`) in one `st.container(horizontal=True)` → `_render_tokenize_row` (see Key Functions): the `Tokenize` button with, beside it as its readout, the utterance-length caption (exact count when `st.session_state["last_phonemes"]` matches the current `(text, lang_code)`, else `~estimate`); the first-use tokenizer spinner and any Tokenize error land full-width below that row → the phoneme expander, which opens itself on a match so tokenized output survives reruns. Its `st.code(phonemes)` is **deliberately unwrapped**, though at a 1440 px window the block then shows only ~50 of a typical 275 phonemes before scrolling: misaki puts its stress marks ˈ/ˌ *inside* words and UAX #14 (class BB) allows a break before them, so `wrap_lines=True` split words there — 3 of 5 breaks at 1440 px were mid-word ("f" / "ˈɑðəɹ"), in English, French and Hindi alike. Streamlit has no wrap-at-spaces-only option, and U+2060 would leak into the text users copy `[word](/phonemes/)` overrides from. (`TestRenderPhonemes.test_renders_expander_and_code` and `TestRenderPersistentPhonemes.test_renders_when_text_and_lang_match` assert the exact call.) The 300 px balances the composer against the voice list rather than holding text (the box scrolls and resizes): at 500 px it pushed Tokenize to the fold at 1440×900; at 300, mid-session at 1440×900, the composer with its phoneme expander open ends at ~778 px and the voice list at ~783 px, with all six Play buttons above the fold (6/6 at 1280×800 too).

`SampleButton` carries `icon` as its own field so the emoji reaches `st.button(icon=…)` rather than the label — concatenating them made the icon part of the accessible name. The emoji are deliberate over Material Symbols: 📕/📗 separate the two excerpts by colour, which a monochrome symbol can't. The buttons keep `wrap=True` for the one case their row cannot absorb — a single label wider than the column — where the label then wraps inside its button instead of ellipsizing ("Pride & …"). (`TestRenderSampleButtons.test_button_labels_wrap`)

**Voices (right column):** one `st.container(gap="xsmall")` holding the top 6 cards by grade, then — when more remain — a `Show all voices (N more)` `st.toggle`, then, only while it is on, the rest; a caption instead when the filter matches nothing. `gap="xsmall"` because an idle card is 72 px tall, so the column's stock 1rem gap was nearly a quarter of one and the list read as six panels rather than one table. The count is in the label because the bare string said a tail existed but not that it was 14 of 20.

**The tail is a toggle inside the list, not an expander around it — keep it that way.** Drawn into the same container, every card shares one width and one Play rail (measured: 402 px at a 1280 px window, 482 at 1440); the expander's border and padding made each tail card 34 px narrower, so at ~1230–1295 px the tail went name-over-controls while the top six stayed one line. And `st.expander` hashes `label` and `expanded` into its element id (`layouts.py`, `key_as_main_identity=False`), so the count in the label remounted it on every filter change and it needed a hand-rolled state mirror to stop clicks being lost; a keyed toggle's id comes from its key alone (`checkbox.py:482`, `key_as_main_identity=True`), so the count changes freely. `key="show_all_voices"` carries `persist_state="session"` because a language or gender filter leaving ≤6 voices (Japanese has 5; British English Female, 4) never draws the toggle, and Streamlit would otherwise discard its state there. Two trade-offs against the expander, both stock `st.toggle` behaviour with no option to change them: it is a native switch, so **Space** flips it but Enter does not (the ARIA switch pattern allows this; the expander's `<summary>` took both), and its click target is its label, not a full-width bar.

**It is lazy and must stay that way.** The tail is built only under `if show_all:` — 14 surplus cards for American English's 20 voices, each a full `st.session_state` scan plus two widgets (speed and Play; three once it has audio and a Download), on every rerun otherwise. A tail card the run skips is an unrendered widget, whose state Streamlit discards: hence `persist_state="session"` on the speed selectbox too. Without it a tail voice snapped back to 1.0x on reshow, and because `_cache_key` includes the speed, that silently demoted its generated clip to a "speed changed" stale preview. `persist_state="page"` holds it too in a real browser (measured: `"session"` and `"page"` both kept 1.3x with the tail hidden and reshown, `None` reset it to 1.0x) — Streamlit documents `"page"` as covering a widget hidden within one page (`runtime/state/widgets.py:106`). It fails only under AppTest, which builds a fresh `PagesManager` per `run()` (`app_test.py:477`): each run starts from page `""`, `script_runner.py:648` reads that as a page switch, and every `"page"` widget the previous run skipped is reset. Keep `"session"`: it is the only scope the guard test can see, and in a single-page app the two are otherwise equivalent. (`TestVoiceCards.test_tail_voice_speed_survives_collapse_and_reopen`)

`TestShowAllVoices` pins the toggle, each test mutation-verified: `test_off_by_default_and_the_tail_is_not_built`, `test_turning_it_on_reveals_every_remaining_voice`, `test_every_click_flips_it` (a lagging mirror loses the second click), `test_its_element_id_survives_clicks_and_a_count_change` (an unkeyed or label-keyed toggle moves its id), `test_stays_on_across_a_filter_change`, `test_stays_on_across_a_language_that_never_draws_it` and `test_stays_on_across_a_filter_that_never_draws_it` (the toggle's `persist_state`, by both routes), `test_tail_cards_share_one_container_with_the_top_six` (any `st.container` or `st.expander` around the tail, or around each tail card, via `_block_shape`); `TestSidebar.test_composer_and_voice_cards_render_in_main` keeps it and every Play in main. They find it by label (`_show_all_toggle`) and flip it with `set_value(...).run()`, which sends the value under the id the last run drew, as a click does — writing `show_all_voices` into session state instead would hide a moved id — and check the tail both against the label's count (`_tail_size`) and against the voice files on disk (`_voices_on_disk`), since the label and the tail come from the same `hidden` list and would agree even if it dropped voices. None of that runs in CI, so `TestShowAllVoicesToggle` in the unit suite re-executes the module body with `runpy` (as `TestFirstLaunchDownloadGuard` does) over an eight-voice snapshot and pins the toggle's key, `persist_state`, label count, and lazy tail.

**Voice card:** one `st.container(horizontal=True, vertical_alignment="center")` row holding the title slot (a bare `st.container()`, whose default stretch width makes the name the row's flexible part) and an `st.container(horizontal=True, width="content", gap="xsmall")` group of speed selectbox and Play, both keyed per voice and `width=CARD_CONTROL_WIDTH` (96 px; measured in the stock theme, Play clips to "P…" at 74 px and fits from 78, and "1.0x" clips at 66). The speed label is collapsed but reads `Speed for <voice title>`: it is still the accessible name, and a bare "Speed" was identical on every card (`TestRenderVoiceCard.test_speed_label_names_its_voice`, `TestVoiceCards.test_each_speed_selectbox_is_labelled_for_its_voice`). So, wide enough, an idle card is one control-height tall and every card's Play button, tail included, sits on one right-aligned rail.

**Both button rows are horizontal containers, not columns** — the reverse of the pre-sidebar rule, and for measured reasons. *Sample row:* beside the sidebar the composer is ~270–500 px, and even thirds of that broke every label mid-word at a 1024 px window ("Rando/m quote", "Frank/enstei/n"); a horizontal container sizes each button from its own label and wraps *whole buttons* onto a new line, at the cost of widths that track label length (`TestRenderSampleButtons.test_buttons_share_one_wrapping_row`). *Card row:* it is fill-plus-fixed, not a proportional grid, and ratio columns could not hold both ends — at a 1024 px window a card is under 300 px, and `[1.6, 1, 1]` left speed and Play 66 px each, truncated to "1.(" and "P…"; at 1920 px the same ratios blew them up to 190 px apiece. Fixed-width controls keep their right edges aligned across cards of one width, and a horizontal container wraps by its *own* width where columns only stack by viewport (≤640 px), so a card too narrow for one line drops the controls under the name. They are grouped to drop as a unit: loose in the row they wrapped one at a time — a short name kept its speed box and sent only Play down — so neighbouring cards broke at different points.

**The one-line card has a transition band — measured, known and accepted.** The row fits one line from ~377 px of card width (the title slot's 8rem flex basis + 2 × 96 px controls + gaps + card padding), the same for every card. Just above the switchover (~1226–1255 px for English, up to ~1300 px for Japanese) some names wrap inside the title slot — breaking before "(gender) — grade", which `_format_voice` holds together, so a card reads "Nicole" over "(female) — B-" — 11–18 px taller than a one-line card; at 1280 px a played card's "Cached" badge wraps under its name.

Should cards ever sit side by side, `height="stretch"` will not equalise them: `st.fragment` wraps its body in its own content-height `st.container()` (`runtime/fragment.py:696`), so a card stretches to that wrapper, not to its row. Measured: a plain stretch container matched its tallest column neighbour; a fragment's did not.

Play generates at the selected speed, stamps `seq`, stores under `_cache_key`, and evicts. Below the row, when the current speed is cached, the player and a WAV Download share an `st.container(horizontal=True, vertical_alignment="center")`: the player takes what Download leaves, and since `st.audio` gets a ~14rem (224 px) flex basis there, a narrow card wraps Download under the player rather than squeezing it to a stub with no seek bar. When only another speed is cached, a "speed changed" caption and then the stale-preview player draw straight into the card, with no Download. Multiple voices' audio coexists for A/B comparison on the same text, bounded at `AUDIO_CACHE_LIMIT`.

**Failure behavior** — every path degrades in place rather than replacing the page:

- First-launch download failure (offline with no cache): `st.error` then `st.stop()` — before the caption and the sidebar are drawn. `TestFirstLaunchDownloadGuard` re-runs the module body with `runpy` under fresh `streamlit`/`huggingface_hub` stand-ins (`patch.dict(sys.modules, …)`, so conftest's shared mocks and `DECORATOR_KWARGS` are untouched) and asserts one error, one stop, no caption, no sidebar.
- Tokenize failure: one `st.error(_tokenize_error_message(...))`, drawn by `_render_tokenize_row` after its row closes, so it spans the column below the row while the caption stays beside the button with its estimate; `_tokenize_error_message` upgrades the Japanese missing-UniDic case to a recovery command.
- Per-card generation: a `ValueError` containing `"No audio generated"` (the only one raised) becomes a clean `st.error`; anything else — including any other `ValueError` — falls through to `st.exception`. Other cards stay functional either way.
- Chunk-by-chunk progress appears via `st.status` inside the active card, rendered into an `st.empty()` placeholder. It is cleared once the clip is stored — a lingering "complete!" block was a third row in a one-row-plus-player card, and vanished on the card's next rerun, jolting the player up — but left in place on failure, where an exception inside `st.status` flips it to its error state, as context above the message.
